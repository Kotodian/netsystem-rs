# Issue Tracker: GitHub

Issues and PRDs for this repo live in GitHub Issues for `Kotodian/hammer-ios-rs`. Use the `gh` CLI for issue operations.

## Conventions

- Create an issue: `gh issue create --repo Kotodian/hammer-ios-rs --title "..." --body "..."`
- Read an issue: `gh issue view <number> --repo Kotodian/hammer-ios-rs --comments`
- List issues: `gh issue list --repo Kotodian/hammer-ios-rs --state open --json number,title,body,labels,comments`
- Comment on an issue: `gh issue comment <number> --repo Kotodian/hammer-ios-rs --body "..."`
- Apply or remove labels: `gh issue edit <number> --repo Kotodian/hammer-ios-rs --add-label "..."` / `--remove-label "..."`
- Close an issue: `gh issue close <number> --repo Kotodian/hammer-ios-rs --reason completed`

## Pull Requests As A Triage Surface

PRs as a request surface: no.

External PRs are not pulled into the `/triage` queue by default. Explicitly named PRs may still be inspected when the user asks for them.

## Skill Routing

- When a skill says "publish to the issue tracker", create a GitHub issue.
- When a skill says "fetch the relevant ticket", run `gh issue view <number> --repo Kotodian/hammer-ios-rs --comments`.
- Every issue comment posted during `/triage` must start with:

```markdown
> *This was generated by AI during triage.*
```
