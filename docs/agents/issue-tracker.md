# Issue Tracker: GitHub

Issues and PRDs for this repo live in GitHub Issues for `Kotodian/hammer-ios-rs`. Use the `gh` CLI for issue operations.

## Conventions

- Create an issue: `gh issue create --repo Kotodian/hammer-ios-rs --title "..." --body "..."`
- Read an issue: `gh issue view <number> --repo Kotodian/hammer-ios-rs --comments`
- List issues: `gh issue list --repo Kotodian/hammer-ios-rs --state open --json number,title,body,labels,comments`
- Comment on an issue: `gh issue comment <number> --repo Kotodian/hammer-ios-rs --body "..."`
- Apply or remove labels: `gh issue edit <number> --repo Kotodian/hammer-ios-rs --add-label "..."` / `--remove-label "..."`
- Close an issue: `gh issue close <number> --repo Kotodian/hammer-ios-rs --reason completed`

## Pull Requests As A Triage Surface

PRs as a request surface: no.

External PRs are not pulled into the `/triage` queue by default. Explicitly named PRs may still be inspected when the user asks for them.

## Skill Routing

- When a skill says "publish to the issue tracker", create a GitHub issue.
- When a skill says "fetch the relevant ticket", run `gh issue view <number> --repo Kotodian/hammer-ios-rs --comments`.
- Every issue comment posted during `/triage` must start with:

```markdown
> *This was generated by AI during triage.*
```

## Wayfinding Operations

Use these operations for `/wayfinder`. A map is one issue labelled
`wayfinder:map`; its tickets are native GitHub sub-issues labelled with exactly
one of `wayfinder:research`, `wayfinder:prototype`, `wayfinder:grilling`, or
`wayfinder:task`.

- Create the map and tickets with `gh issue create`, then attach each ticket
  with the GraphQL `addSubIssue` mutation. `issueId` is the map's GraphQL node
  ID and `subIssueId` is the ticket's GraphQL node ID.
- Express blocking with the native `addBlockedBy` mutation. `issueId` is the
  blocked ticket and `blockingIssueId` is its blocker. Do not duplicate native
  edges in issue bodies.
- Query the frontier from the map's ordered, open `subIssues`: discard any
  ticket whose `blockedBy` connection contains an open issue, then discard any
  ticket with an assignee. The first remaining ticket is the next frontier
  item.
- Claim a ticket before doing work with
  `gh issue edit <number> --add-assignee @me`.
- Resolve exactly one ticket per session: post the answer as a resolution
  comment, close the ticket, and append only a one-line linked gist to the
  map's `Decisions so far` section.

GitHub REST `id` values, issue numbers, and GraphQL node IDs are distinct. Read
the node IDs used by these mutations with a repository GraphQL query; never
substitute an issue number for a node ID.
