## Destination

Replace static network assembly with four dynamic plugin crates:
`hammer-plugin-tun`, `hammer-plugin-ip`, `hammer-plugin-tcp`, and
`hammer-plugin-udp` (`.so` on Linux and `.dylib` on macOS).

`device`, `interface`, `transport`, and `session` remain shared infrastructure,
not plugins. The daemon supports startup root selection, loaded-plugin
inspection, and VPP-shaped additive loading through one process-global
`PluginMain`. Successfully activated library handles remain mapped until
process exit. `hammer-app` remains the client Rust SDK, and UDP does not gain
session semantics.

## Authority And Constraints

- Use the vendored `third_party/vpp` loader, main-thread graph registration,
  worker barrier/graph publication, frame batching, and session/transport ownership as the
  semantic authority.
- Plugin loading and configured instance creation are separate. Empty root
  configuration may load no plugins and create no instances; a late-loaded
  plugin may still consume its existing configuration section.
- The declared plugin dependency graph is `tcp -> ip` and `udp -> ip`; `tun`
  and `ip` have no plugin dependency. Shared infrastructure is not represented
  as a plugin dependency.
- Plugins publish registration inventory, Graph Nodes, and typed named Next
  Arcs. The main-thread Graph Runtime exclusively registers nodes, resolves
  names, and publishes the updated graph to workers. Workers never mutate topology.
- `hammer-core` owns canonical data-plane types and the registration contract.
  Do not add shadow Frame/Buffer types, View types, owner wrappers, carriers,
  payload copies, temporary payload Vecs, or per-packet ABI dispatch.
- Ordinary production allocation uses Hammer's main heap and `hammer-infra`;
  only SVM regions and Buffer Arena packet storage are exempt.
- Any new non-trivial type or interface requires the approval section mandated
  by `AGENTS.md` before implementation.

## Decisions So Far

- [#99](https://github.com/Kotodian/hammer-ios-rs/issues/99): VPP owns
  load/constructor/Graph/barrier/frame/session-transport semantics and has no
  activated-plugin unload protocol.
- [#97](https://github.com/Kotodian/hammer-ios-rs/issues/97): canonical
  Index/buffer-header/Frame contracts work through a DSO Node function;
  `abi_stable::RootModule` is rejected because it leaks the library handle.
- [#95](https://github.com/Kotodian/hammer-ios-rs/issues/95): retain the
  `PluginRegistration` plus SemVer contract; reject parallel RootModule,
  registrar, service-lease, and shadow data-plane surfaces.
- [#92](https://github.com/Kotodian/hammer-ios-rs/issues/92): the loader owns
  platform path resolution, dependency expansion, registration images,
  configuration text, rollback before activation, and process-lifetime handles.
- [#100](https://github.com/Kotodian/hammer-ios-rs/issues/100): main-thread
  graph rebuild drains and renumbers, rebinds by name, and publishes one
  identical topology to workers.
- [#96](https://github.com/Kotodian/hammer-ios-rs/issues/96): `tun`, `ip`,
  `tcp`, and `udp` ship as DSOs; `device`, `interface`, `transport`, and
  `session` remain shared infrastructure; plugin named Next Arcs are resolved
  uniformly by Graph Runtime.
- [#94](https://github.com/Kotodian/hammer-ios-rs/issues/94): static plugin
  assembly and its superseded compatibility path are removed.
- [#103](https://github.com/Kotodian/hammer-ios-rs/issues/103): additive plugin
  loading now dispatches only newly published lifecycle inventory, extends the
  main-thread Graph Runtime, publishes one updated graph to live workers, and
  exposes plugin list/load through daemon IPC and `hammerctl`.
- [#104](https://github.com/Kotodian/hammer-ios-rs/issues/104): one
  process-global fixed-capacity mimalloc Main Heap now owns ordinary
  post-`READY` allocation without fallback; bootstrap allocation remains on
  the operating-system allocator, and Buffer Arena/SVM mappings retain their
  explicit ownership domains.
- [#98](https://github.com/Kotodian/hammer-ios-rs/issues/98): the real four-DSO
  plugin system, additive Graph publication, allocation ownership, failure
  behavior, and dataplane performance gates are verified on Linux and macOS.

## Open Path

None. The destination is complete: all wayfinder research, prototype,
implementation, and verification tickets are closed.

## Out Of Scope

- Activated plugin enable/disable, inventory filtering, dependency retirement,
  draining to unload, or `dlclose`; [#93](https://github.com/Kotodian/hammer-ios-rs/issues/93)
  is closed as not planned.
- Replacing or hot-upgrading a loaded library file.
- QUIC plugin work.
- Plugin signing, trust policy, or provenance enforcement.
- Adding session semantics to UDP.
- Moving `hammer-app` away from its role as the client Rust SDK.
