# HugeTLB Main Heap & Buffer Arenas Implementation Plan (Issue #121)

   > **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or
   `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Any item in
   **Approval Gate** must be shown to the user and approved before Rust implementation.

   **Goal:** Add VPP-aligned Linux HugeTLB backing for the process-global Main Heap and per-NUMA Buffer Arenas. Explicit hugepage requests
   are real kernel HugeTLB pages on the requested NUMA node or startup fails; omitted Buffer page size follows VPP's try-default-hugepage
   / warn / fall-back-to-ordinary behavior. SVM/session mappings are out of scope.

   **Architecture:** `hammer-infra` owns one generic `PageSize` vocabulary and one strict lower-layer mapping primitive (page resolution,
   sysfs discovery/provisioning, scoped `MPOL_BIND`, exact memfd/anonymous mapping, pre-touch, verification, RAII). `hammer-core` Buffer
   Arena construction becomes fallible and accepts a resolved page size. `hammer-runtime` owns config parsing, omitted-vs-explicit Buffer
   policy, warn/fallback, topology resolution, and one-time final arena creation. `hammer` owns bootstrap ordering: parse early config on
   System, pin main core, resolve NUMA, publish Main Heap, then build everything else exactly once.

   **Tech Stack:** Rust 2024, `libc` (`memfd_create`, `MFD_HUGETLB`/`MFD_HUGE_*`, `mmap`/`MAP_HUGETLB`, `get_mempolicy`/`set_mempolicy`,
   `move_pages`, `sched_setaffinity`), Linux sysfs (`/sys/kernel/mm/hugepages`, per-node `hugepages`), `/proc/meminfo`,
   `/proc/self/{smaps,numa_maps}`, locked `libmimalloc-sys 0.1.49` (mimalloc v3.3.2: `mi_manage_os_memory_ex`, `mi_arena_area`,
   `mi_arena_min_alignment`, `mi_arena_min_size`, `mi_option_limit_os_alloc`), local VPP reference under `third_party/vpp`.

   ## Global Constraints

   - One public generic page-size vocabulary owned by `hammer-infra`: `"default"`, `"default-hugepage"`, explicit binary size (`"2 MiB"`,
   `"1 GiB"`). Never expose `log2_page_size` in config or new public APIs.
   - The infra mapping primitive is strict: it never implements Buffer fallback internally; it returns typed errors and `hammer-runtime`
   owns policy.
   - Semantics table (must be exact):

     | Domain | Field omitted | `"default"` | `"default-hugepage"` / explicit huge |
     | --- | --- | --- | --- |
     | Main Heap | ordinary pages | ordinary pages | strict HugeTLB; startup fails on any provisioning/mapping/registration/placement
   failure |
     | Buffer Arena | try default HugeTLB; one warning with typed cause, then strict ordinary retry | strict ordinary pages | strict
   HugeTLB; no fallback |

   - Non-Linux: omitted/`"default"` keeps working; any explicit hugepage request is rejected at configuration validation.
   - Provision per-NUMA `nr_hugepages` by shortfall only; never shrink or roll back global state, even after later startup failure. The
   final `mmap` is authoritative (another process can race the pool between sysfs reads and mapping).
   - THP is never accepted as HugeTLB. No `mlock`. No hugetlbfs mount fallback. No runtime page-size changes.
   - Main Heap stays one process-global fixed-capacity ordinary-allocation authority; exhaustion after `READY` must not create any new OS
   mapping.
   - Range `mbind` does not work for `MAP_SHARED` file mappings on Linux — Buffer memfd mappings must use the scoped thread
   `set_mempolicy(MPOL_BIND)` guard, with the exact prior policy restored on every success and error path.
   - Layer contract: infra may touch libc/sysfs/mempolicy/mmap/memfd/mimalloc and must not know Buffer
   fallback/topology/TOML/Engine/sessions. Core owns packet storage + `PhysmemMap` retention and must not read sysfs/config, provision,
   log fallback, or fall back to Main Heap. Runtime owns config/policy/topology/one-time arena creation and must not issue raw HugeTLB
   mmap flags. `hammer` owns bootstrap ordering and duplicates none of the lower layers.
   - No allocator-specific type may escape `hammer_infra::main_heap`. No business type may enter the generic page-mapping layer.
   - Typed errors everywhere: preserve source `io::Error`/errno plus structured context (domain, requested/rounded bytes,
   requested/resolved page size, NUMA node, required/free/current/attempted page counts, which syscall/sysfs step failed). If NUMA policy
   restore fails after a primary failure, preserve both facts.
   - Do not add source-text assertion tests. Normal `cargo test --workspace` must not require root, preconfigured hugepages, or writable
   sysfs.
   - TDD rhythm per task: write the named failing test, run red, implement minimum, run green, commit.

  ## Global Constraints

  - One public generic page-size vocabulary owned by `hammer-infra`: `"default"`, `"default-hugepage"`, explicit binary size (`"2 MiB"`, `"1
  GiB"`). Never expose `log2_page_size` in config or new public APIs.
  - The infra mapping primitive is strict: it never implements Buffer fallback internally; it returns typed errors and `hammer-runtime` owns
  policy.
  - Semantics table (must be exact):

    | Domain | Field omitted | `"default"` | `"default-hugepage"` / explicit huge |
    | --- | --- | --- | --- |
    | Main Heap | ordinary pages | ordinary pages | strict HugeTLB; startup fails on any provisioning/mapping/registration/placement failure
  |
    | Buffer Arena | try default HugeTLB; one warning with typed cause, then strict ordinary retry | strict ordinary pages | strict HugeTLB;
  no fallback |

  - Non-Linux: omitted/`"default"` keeps working; any explicit hugepage request is rejected at configuration validation.
  - Provision per-NUMA `nr_hugepages` by shortfall only; never shrink or roll back global state, even after later startup failure. The final
  `mmap` is authoritative (another process can race the pool between sysfs reads and mapping).
  - THP is never accepted as HugeTLB. No `mlock`. No hugetlbfs mount fallback. No runtime page-size changes.
  - Main Heap stays one process-global fixed-capacity ordinary-allocation authority; exhaustion after `READY` must not create any new OS
  mapping.
  - Range `mbind` does not work for `MAP_SHARED` file mappings on Linux — Buffer memfd mappings must use the scoped thread
  `set_mempolicy(MPOL_BIND)` guard, with the exact prior policy restored on every success and error path.
  - Layer contract: infra may touch libc/sysfs/mempolicy/mmap/memfd/mimalloc and must not know Buffer fallback/topology/TOML/Engine/sessions.
  Core owns packet storage + `PhysmemMap` retention and must not read sysfs/config, provision, log fallback, or fall back to Main Heap.
  Runtime owns config/policy/topology/one-time arena creation and must not issue raw HugeTLB mmap flags. `hammer` owns bootstrap ordering and
  duplicates none of the lower layers.
  - No allocator-specific type may escape `hammer_infra::main_heap`. No business type may enter the generic page-mapping layer.
  - Typed errors everywhere: preserve source `io::Error`/errno plus structured context (domain, requested/rounded bytes, requested/resolved
  page size, NUMA node, required/free/current/attempted page counts, which syscall/sysfs step failed). If NUMA policy restore fails after a
  primary failure, preserve both facts.
  - Do not add source-text assertion tests. Normal `cargo test --workspace` must not require root, preconfigured hugepages, or writable
  sysfs.
  - TDD rhythm per task: write the named failing test, run red, implement minimum, run green, commit.
