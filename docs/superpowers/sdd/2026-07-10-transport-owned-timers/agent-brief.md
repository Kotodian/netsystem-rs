## Agent Brief

**Category:** enhancement
**Summary:** Move transport state and exact timer policy out of generic Session Runtime and behind statically dispatched transport workers.

**Current behavior:**
Session Runtime owns a shared timer wheel and tick conversion, exposes raw timer-wheel access to protocol code, stores TCP connection state in generic session entries, and delivers raw timer ids. TCP reconciles every timer kind after unrelated protocol operations. The generic protocol interface also combines TCP-shaped packetized TX with an optional custom TX path.

**Desired behavior:**
Session Worker owns only app/session FIFOs, readiness, lifecycle coordination, and session scheduling. Separate transport workers own generation-safe protocol object pools, lookup, clocks, timer wheels, exact timer tokens, and protocol dispatch. SessionQueueNode samples one absolute time per dispatch and statically updates each registered transport before session control and I/O work. TCP owns typed armed/pending timer state and dispatches only the exact expired timer kind. The generic boundary supports both TCP Session-Packetized TX and a QUIC-shaped Transport-Internal TX strategy without dynamic dispatch.

**Key interfaces:**
- `SessionTransport<Index, Seg>`: generic, statically dispatched transport integration whose associated TX strategy makes incompatible packetization paths explicit.
- `SessionEntry<Index>` and typed `SessionState<Index>`: transport-neutral dispatch/index storage plus legal app/transport ownership transitions; Transport Deleted carries no index.
- `TcpWorker<C>`: worker-local owner of TCP connections, lookup, clock, timers, exact-token dispatch, and TCP TX policy.
- Private typed TCP timer kind/set/state and timer owner: distinguish wheel-armed from pending expiry; rearm/reset make obsolete tokens stale.
- Session Worker transport-neutral operations: FIFO access, ACK cleanup, RX enqueue, readiness, and lifecycle notification, including one transport event affecting multiple future QUIC stream sessions.

**Acceptance criteria:**
- [ ] Session modules contain no TCP/QUIC connection types, timer kinds/counts/masks, keep-mask semantics, timer wheel, transport tick conversion, or exact timer dispatch.
- [ ] TCP owns its connection pool and timer wheel and handles retransmit, RACK, TLP, delayed ACK, persist, keepalive, TIME_WAIT, and pacing through exact typed tokens without scanning all kinds.
- [ ] Set/update/reset immediately synchronize TCP timer ownership; reset clears armed and pending state, and rearm/stale-generation cases cannot dispatch obsolete expiry.
- [ ] SessionQueueNode supplies one absolute time to a compile-time transport set before session control and I/O, while each transport owns resolution and expiry budget.
- [ ] TCP continues to send from session-owned FIFO bytes through Session-Packetized TX, and a QUIC-shaped test transport proves Transport-Internal TX and multi-session lifecycle fan-out without TCP semantics.
- [ ] Typed Session Lifecycle covers app-first close, transport-first close, Closed retaining the Transport Index, delayed transport cleanup, and Transport Deleted carrying no index.
- [ ] `TcpQueue`, the old per-connection protocol interface, raw TCP timer constants/count/masks, full-timer reconciliation, and tick-based Session polling are removed.
- [ ] Existing TCP behavior tests plus new boundary, lifecycle, exact-token, stale-token, ordering, and architecture guardrail tests pass.
- [ ] Formatting, clippy, and the full workspace test suite pass.

**Out of scope:**
- Production QUIC implementation, cryptography, packet formats, congestion control, or public stream APIs.
- Changes to congestion-control ownership, the app/session FIFO boundary, or payload retention/copy rules.
- Dynamic dispatch, runtime transport plugins, a TCP/QUIC enum in Session Runtime, or a shared generic runtime timer service.
- New hammer-infra APIs unless a separately justified shared primitive is approved.
