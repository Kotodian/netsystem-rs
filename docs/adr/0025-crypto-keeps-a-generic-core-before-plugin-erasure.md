# Crypto keeps a generic core before plugin erasure

The primitive core uses the closed `Family` markers `Aead`, `Cipher`, `Hash`, `Mac`, `Kdf`, `Kx`, `Sign`, and `Verify` to parameterize `AlgorithmId<F>`, `Context<F>`, and `Batch<'_, F>`, while plugins keep the algorithm and implementation sets open within each family. The exchange core uses `exchange::Protocol<C>` with protocol-owned parameter, state, established-result, and error types, represented by `exchange::Exchange<P, C>` and `exchange::Transition<S, E>`. Each concrete plugin protocol is monomorphized in its own link image and erased once into an ABI-stable registration function table at the DSO seam; primitive execution performs one indirect call per batch rather than per operation, and no Adapter wrapper type is introduced. This preserves Rust type checking and static dispatch inside each module without pretending that plugin types can cross a dynamic-library ABI unchanged.
