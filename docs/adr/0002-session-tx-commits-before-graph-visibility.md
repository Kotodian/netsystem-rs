# Session TX commits before graph visibility

Hammer Session Runtime TX must not make a packet visible to the Packet Graph before transport state is committed. This follows VPP session TX ordering: session TX fills data-plane buffers from session-owned TX FIFO bytes, TCP `push_header` advances transport state such as `snd_nxt` and retransmit timer state, and only then does the session queue flush pending TX buffers to the next graph node. This prevents a packet from leaving the TX Transaction while TCP sequence, recovery, and timer state still describe the packet as unsent.

Hammer keeps TCP Output Intent materialization and transport state commit in one Transport TX Action over a TX Batch instead of splitting them across separately ordered Session Runtime callbacks. Normal TCP TX retains VPP `TRANSPORT_TX_PEEK` semantics: packetization may copy bytes from the Session FIFO into data-plane buffers, but only ACK cleanup may drop retained TX bytes from the Session FIFO. The SessionQueueProtocol seam follows VPP's two-step shape: transport first supplies Transport-Neutral TX Facts such as send space, TX offset, send goal size, and scheduling flags; after Session Runtime prepares a TX Batch, transport performs one batch action equivalent to VPP `push_header`. The seam is not separate `prepare_tx`, `cancel_tx`, and `commit_tx` transaction steps, and Session Runtime does not request or construct TCP Output Intent.

Fallible TX work happens before the Transport TX Action. Once that action is called for a prepared batch, it materializes the TCP Output Intent and commits transport state for the batch; Session Runtime does not get a cancellation, rollback, or half-commit repair protocol. TX-side recovery and timer updates belong inside the Transport TX Action. Session Runtime TX remains fully isolated from TCP header fields, `TcpSegment` construction, TCP recovery records, timer masks, and TCP Output Intent materialization.

A committed TX Batch is made visible to the Packet Graph through a Session Runtime TX Batch Flush after the Transport TX Action, not through per-buffer pre-commit `put_next_frame` calls or TCP-owned output carriers. The seam must be wide enough for GSO: transport send facts include a Send Goal Size that Session Runtime uses for packetization, while GSO flags, offload metadata, TCP option length, and TCP header semantics remain in transport/output code. Buffer APIs stay transport-neutral and provide generic headroom, chain, and refcount behavior instead of TCP/GSO-specific ownership or packetization APIs.

A TX Batch is the commit and visibility unit. All buffers prepared for one TX Batch remain invisible while pending in Session Runtime, are committed by one Transport TX Action, and become graph-visible only through the following TX Batch Flush. Hammer must not partially commit or partially flush a batch buffer-by-buffer.

The normal Session Runtime TX seam is only for new data packetized from the Session FIFO. TCP retransmit, ACK-only output, persist probes, delayed ACKs, and other special TCP output follow a transport-owned custom TX path analogous to VPP `custom_tx`; they do not share the normal new-data TX Batch seam and do not expose TCP header construction to Session Runtime.

TX FIFO cleanup follows VPP `TRANSPORT_TX_PEEK`: normal TX peeks or copies session-owned TX bytes into data-plane buffers, and neither Transport TX Action nor TX Batch Flush releases those bytes. Only TCP ACK cleanup may compute newly acknowledged payload bytes and ask Session Runtime to drop them from the Session FIFO. Retransmit paths therefore always packetize from session-owned retained bytes plus TCP recovery facts, not from private TCP payload copies.

Transport owns send eligibility facts, while Session Runtime owns ready-queue mechanics. Transport may report send space, TX offset, send goal size, pacing readiness, deschedule, or postpone facts; Session Runtime decides whether to keep, requeue, deschedule, or later mark the session ready. TCP and congestion control do not schedule graph nodes or directly own the Session Ready Queue.

Session Runtime timer ownership is limited to generic timer storage and exact Timer Token dispatch. TCP transport interprets the token, handles TCP timer semantics, and arms or cancels TCP timers through transport-owned logic. Session Runtime and the normal TX seam must not scan TCP timer kinds, consume TCP timer masks, or discover expired TCP work by iterating transport timers.

The implementation should replace the old external TX seam in one move rather than layering a compatibility wrapper over `prepare_tx`, `cancel_tx`, and `commit_tx`. Internal implementation steps may be staged, but the exposed SessionQueueProtocol shape should move directly to the VPP-style send-facts plus batch action model so the old per-buffer and rollback protocol cannot keep influencing callers.

The approved external TX surface is limited to VPP-shaped operations: `send_params` returns transport-neutral send facts, `push_header` commits a prepared TX Batch, `custom_tx` handles transport-owned special output, `handle_expired_timer` dispatches the exact Timer Token, and ACK cleanup continues through Session Runtime's ACK-drop path. `TransportSendParams` carries only send space, TX offset, Send Goal Size, and scheduling flags such as deschedule or postpone. `push_header` receives batch buffer facts and owns TCP Output Intent construction, `snd_nxt` advancement, and TCP timer/recovery updates.

**VPP evidence:** VPP's transport vft exposes `send_params`, batched `push_header`, and `custom_tx` in `third_party/vpp/src/vnet/session/transport.h`. The session node gets transport send facts, handles no-space `DESCHED`/`POSTPONE` scheduling, computes dequeue parameters, fills multiple buffers, records them as pending TX buffers, then calls `push_header` once over the pending buffer batch in `third_party/vpp/src/vnet/session/session_node.c`. TCP registers `TRANSPORT_TX_PEEK`, `send_params`, `push_header`, and `custom_tx` in `third_party/vpp/src/vnet/tcp/tcp.c`; `tcp_session_push_header` walks the buffer batch, prepends TCP headers, advances `snd_nxt`, starts RTT/retransmit tracking, and keeps these TCP details out of session code in `third_party/vpp/src/vnet/tcp/tcp_output.c`. ACK cleanup drops retained TX FIFO bytes via `session_tx_fifo_dequeue_drop` in `third_party/vpp/src/vnet/tcp/tcp_input.c`. For TSO/GSO, TCP changes the send-size fact to `tcp_session_cal_goal_size`, while output later marks buffers with `VNET_BUFFER_F_GSO` and `gso_size`; session still only consumes the send-size fact.
