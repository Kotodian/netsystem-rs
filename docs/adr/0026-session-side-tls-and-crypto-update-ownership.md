# Session-side TLS ownership through rustls

Status: accepted; supersedes ADRs 0017 through 0025

The trusted Hammer daemon terminates application-selected TLS at the App/Session Seam through a session-side TLS plugin, rather than in `hammer-app` or inside generic Session Runtime. Hammer retains one payload-agnostic `AppSession` abstraction at every level of the App Session Stack. App connection policy fixes the Stack when constructing the connection; it is not a mutable mode inside `AppSession`.

Without TLS, the chain contains one `AppSession` between the external App and the selected transport. `session::ProtocolChain<P, L>` owns the App-facing `AppSession`, one concrete protocol state, and its complete lower chain. With TLS, the chain owns an ordinary lower `AppSession` whose FIFOs contain TLS records and a TLS protocol state that receives only the adjacent source and destination FIFO borrows. Its upper `AppSession` carries the immediately higher layer's protocol data. Both levels reuse the same `AppSession` implementation. `AppSession` does not interpret its data or own TLS state, and Hammer does not introduce a TLS-specific Session type, FIFO type, or Session wrapper.

The plugin consumes only adjacent transport-neutral FIFO borrows and requires ordered reliable stream semantics; it neither receives an `AppSession` nor accesses any concrete transport implementation. The Protocol Chain owns ordered traversal and publishes Session events from the byte counts reported by each successful protocol step.

rustls owns the wire grammar, handshake state, transcript, authentication, key schedule, traffic keys, record buffering, and record protection. The Main Thread retains immutable `Arc<ClientConfig>` or `Arc<ServerConfig>` values. Each owning Data Worker constructs, exclusively owns, advances, and drops its concrete `rustls::Connection`. Hammer has no Crypto Engine, Key Handle, Crypto Context, algorithm catalog, implementation registry, or traffic-key provisioning path.

`hammer_infra::Fifo` implements nonblocking `Read`, `BufRead`, and `Write`. TLS record ingress passes the lower RX FIFO directly to `rustls::Connection::read_tls`; record egress passes the lower TX FIFO directly to `write_tls`. The rustls plaintext `Reader` and `Writer` exchange the current upper FIFO segment without a TLS-private payload copy. Once rustls accepts source bytes, rustls owns that buffered protocol state and Session consumes the corresponding source FIFO bytes. One protocol step performs one such transfer. The chain publishes the exact FIFO advancement and repeats within the same Session Queue dispatch until no adjacent FIFO position moves. Destination backpressure ends that dispatch without discarding the drain obligation; a later Session Queue dispatch resumes it after capacity becomes available.

Session Queue remains a VPP-style Input/Driver Node. Every dispatch captures one monotonic `now`, passes it to each installed Transport before control or IO work, and thereby advances Transport-owned timer wheels even when no App event is pending. Until the runtime provides a deadline wake source equivalent to VPP's adaptive timerfd, an installed Transport with active timer-wheel state keeps Session Queue in `Polling`; Session owns neither the wheel nor timer kinds.
