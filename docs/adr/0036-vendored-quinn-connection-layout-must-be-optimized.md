# Vendored quinn Connection layout must be optimized

Status: accepted

The vendored `quinn-proto` remains Hammer's QUIC protocol engine, but its current `quinn_proto::Connection` layout is not an acceptable final per-connection footprint. On the current development target with default features disabled, `Connection` measures 6016 bytes with 16-byte alignment before counting its heap-backed maps, queues, crypto state, stream state, and packet records. Hammer must carry a focused vendored layout patch before QUIC integration is complete; wrapping the unchanged type in `Box` is sufficient to keep stream `QuicCtx` slots small, but is not itself a connection-memory optimization.

The layout follows VPP's ownership boundary before applying any Quinn-specific optimization. VPP keeps one cache-line-aligned `quic_ctx_t` pool per worker and stores the protocol-engine connection out of line through `quic_ctx_t::conn`. It does not impose `cacheline0` or `cacheline1` on `quicly_conn_t`. Hammer therefore aligns the worker context and context-pool slots with `hammer_infra::align::CacheLine`, while `quinn_proto::Connection` remains separately owned through one connection pointer. The Quinn layout must not claim a VPP cache-line partition that VPP does not define.

VPP's first two context cache lines come from `transport_connection_t`. `cacheline0` contains the 44-byte protocol-specific connection-ID overlay followed by IP/protocol, Session index, context index, thread index, and transport flags. QUIC overlays that first 44 bytes with either connection fields (`conn`, listener context, client opaque value, server hostname, connection state, and UDP address-family fact) or stream fields (`stream`, bytes written, and parent QUIC connection context). `cacheline1` contains only the generic transport pacer and padding. QUIC timers, parent Application identities, crypto configuration, limits, keys, and exceptional state begin after those transport cache lines. VPP's `quic_ctx_t` is therefore larger than one cache line; its design requirement is aligned worker-local slots and an out-of-line protocol connection, not a 64-byte total context.

Hammer uses the same `Context` type in its per-thread QUIC context pools. Every slot is one `CacheLine<ContextRole>`: `cacheline0` contains the selected Listener, Connection, or Stream role payload and padding, and both its size and alignment are exactly 64 bytes. There is no QUIC `cacheline1`. VPP's second context cache line contains the generic transport pacer, whose Hammer owner is the existing transport/session layer; copying it into QUIC would duplicate mutable state. Hammer likewise does not copy VPP's generic transport tuple, thread index, Session index, or context index because the UDP Session, owning worker, Session entry, and pool handle already provide those facts.

VPP allocates listener contexts from thread 0's context pool and connection or stream contexts from their owning worker's context pool. Hammer preserves that ownership without sharing one mutable pool across threads: `QuicMain` owns a Main Thread-only `Pool<Context>` containing Listener roles, while each `QuicWorker` owns a `Pool<Context>` containing Connection and Stream roles. Both pools use the same context type, layout, generation-checked handle, and allocation rules. Main Thread listener control never mutates a Data Worker pool, and Data Workers never mutate the Main Thread listener pool.

The Listener payload retains only the upper QUIC listener identity, lower UDP listener identity, and immutable configuration identity required to create accepted connections. The Connection payload retains one owning pointer to `quinn_proto::Connection`, the connected UDP Session identity, and the pending-or-published upper QUIC Session binding. The Stream payload retains its parent Connection context handle, upper Session identity, Quinn stream identity, and `bytes_written` FIFO offset. The pool handle supplies the context identity and generation for every role. Compile-time assertions verify `size_of::<Context>() == 64` and `align_of::<Context>() == 64`.

A stream context remains entirely inline. A connection context retains one pointer to larger Quinn protocol state, matching VPP's `quic_ctx_t::conn` shape, but connection state remains worker-owned and allocated only from the Hammer Main Heap. Cold diagnostics, variable-length server names, endpoint routing collections, crypto configuration, and handshake-only state do not inflate every pool slot. Moving such state out of line is accepted only when ownership is explicit and its resident bytes and hot-path pointer dereferences are measured.

Acceptance requires compile-time assertions for the one-line `Context` slot, checked budgets for every role and the patched Quinn `Connection`, and measured total bytes for handshaking and idle established connections. Benchmarks must cover connection density, packet receive/send, ACK/loss processing, timeout advancement, and stream open/close before and after the patch. The final Quinn budgets are set from the field-layout audit and benchmark results rather than by moving memory out of `size_of` accounting. QUIC correctness, zero-copy Session FIFO behavior, and the existing worker-owned no-lock data path must remain unchanged.
