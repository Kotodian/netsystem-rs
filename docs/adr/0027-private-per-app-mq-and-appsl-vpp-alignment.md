# Private per-app message queues and appsl-rx-mqs-input VPP alignment

Status: accepted

Hammer's app-to-session events move from one shared per-worker `tx_evt_q` to private per-Application message queues, one per Data Worker, owned by `ApplicationMain` and published once at attach. `appsl-rx-mqs-input` becomes the VPP-shaped input driver that keeps a worker-local pending list of these MQs, drains each MQ by snapshot, marks leftovers POSTPONED, and puts events directly into Session Worker event lanes instead of staging them through `session_evt_q`. This decision prioritizes external Application performance and isolation; one Application filling its MQ cannot block another.

Consequences: `ApplicationMain::attach()` creates an `ApplicationMqResources` set and installs every Data Worker registration before returning; attach failure rolls back. External and local Applications both use per-app MQs; local uses local segments, external uses shared segments. `network.session.app_mq_capacity` controls MQ capacity (default 2048, min 128). The attach protocol is versioned and publishes `rx_mqs_segment` plus one write descriptor per Data Worker; `accept()` no longer sends per-session TX event MQ descriptors. `SessionWorker` replaces app-event staging with generic `LinkedList`-based ctrl/new/old event lanes; `appsl` wakes `session-queue` only when worker state is Interrupt. Worker state and timerfd follow VPP; transport TimerWheel remains transport-owned and continues to be advanced by session-queue `update_time`. Session Worker readiness and adaptive deadline registrations are worker-local resources and must be removed while the owning `FileMain` is alive; a stopped Data Worker is not re-entered or restarted through its retained `SessionMain` slot. This supersedes the ADR-0026 statement that `session_evt_q` is the only protocol-progress queue for external app events.
